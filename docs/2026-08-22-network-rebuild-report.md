## 1. 글쓰기 엔진 — Gemini → GPT 우선

- 새로 만든 `refresh_keyword_pool.py`(키워드 리서치)도 동일 원칙 — OpenAI
  Responses API의 `web_search` 툴을 실사용 테스트로 검증 후 적용, Gemini
  검색그라운딩은 최후 폴백으로 격하.
- **10월 지원종료 대응**: `gpt-image-1`(2026-10-23 종료 예정)이 실패하면
  코드가 자동으로 `gpt-image-1.5`로 전환하는 안전망 추가(`openai_text.py`).
  Gemini 2.5 계열(flash-lite/flash/flash-image)은 **2026-10-16 전체 종료
  예정** — 아직 폴백 경로에 남아있어 그 전에 추가 조치 필요(미해결 항목,
  9번 참고).

## 2. 획일화 문제 — "매번 똑같은 값 = AI 대량생산 흔적"

발견된 순서대로:
- **태그**: 부족분을 `"{키워드 전체} 효능"` 식으로 채우던 버그 — 키워드가
  여러 단어면 태그 절반이 사실상 같은 문구 반복이었음. 키워드 통째 반복 제거,
  개수 9~13개 랜덤(사용자 재지시로 10~14→9~13 조정).
- **제목**: 영문 키워드가 소문자 그대로 템플릿에 꽂혀 부자연스러웠던 것
  Title Case로 교정. (템플릿 자체는 유지 — AI가 자유롭게 쓰면 반복 패턴이
  더 심해졌던 과거 사고 때문에 일부러 템플릿+반복방지 구조로 만든 것.)
- **이미지 ALT**: 본문 이미지 여러 장이 전부 동일 ALT였던 것을 위치별(제목/
  키워드/키워드+테마)로 다르게.
- **이미지 개수/글자수**: 26개 사이트 전부 고정값이었던 것을 사이트별 랜덤
  범위로 전환(`resolve_min_chars`), 이미지 장수도 2~3장 랜덤.
- **문장 리듬(문체)**: "톤앤매너 글씨체 다 달라야 해" 지시로, 26개 사이트가
  전부 동일했던 문장구조 규칙("모든 문단 2문장 이하")을 5가지 리듬
  (punchy/flowing/scannable/formal/conversational)으로 나눠 사이트별 고정
  배정 — 특히 금융/건강/교육/구직 인접군은 서로 다른 리듬이 되도록 수동 배정.

## 5. 키워드 풀 — 25개 사이트 50개씩, 네트워크 전체 중복방지

- koreainvest365 첫 시도에서 새 키워드 50개 중 19개(38%)가 **이미 발행된
  글과 겹치는** 걸 발견(예: "Korea money market fund"는 기존 제목과
  완전 동일) — 새 키워드끼리만 대조하고 실제 발행이력과 대조 안 한 게 원인.
  실 발행이력 74건 가져와 어간(stemming) 대조로 재검증·교체.
- 이 교훈을 반영해 `refresh_keyword_pool.py`를 25개 사이트 전체로 확장 —
  매 갱신마다 **25개 사이트 전체의 실제 발행이력을 코퍼스로 만들어** 새
  키워드가 자기 사이트뿐 아니라 인접 사이트와도 안 겹치는지 확인, 부족하면
  재리서치(최대 3라운드), 그래도 부족하면 코퍼스와 안 겹치는 기존 키워드로
  50개 유지.
- 1차 실행(GPT 웹서치 파서 버그로 인해 다수 사이트가 "후보 0개") 발견 후
  파서 수정(탭 없는 응답도 처리, 배치 내 근접중복도 어간 대조로 제거).
  **수정된 파서로 25개 사이트 전체 재검증은 아직 안 함 — 다음 실행에서 확인
  필요.**
- 매주 일요일 자동 재조사(`weekly-keyword-refresh.yml`) 설정 완료.

## 7. jobkorea 계열 3사이트 — 도메인/전략 정리

- `jobkoreaglobal.com`: DNS 미해결 발견 → WHOIS 조회로 clientHold 확인 →
  실제로는 가비아 계정상 2026-08-14 만료(WHOIS 레지스트리 표시 날짜와
  불일치했음, 실제 계정 화면이 맞았음) → 사용자가 가비아에서 즉시 연장
  결제 완료. DNS 전파 대기 중(결제 시점 기준 아직 미확인).
- 색인율 비교(GSC): jobkoreaglobal 23.8%(1위) > jobkorea365 15.9% >
  jobinkorea365 12.3%. jobkoreaglobal은 고용주 대상(B2B)이라 나머지 둘
  (둘 다 구직자 대상)과 겹치지 않음 → **3개 유지가 아니라 jobkoreaglobal
  (B2B) + jobkorea365(구직자, 통합 대상) 2체제로 정리 결정.**
  jobinkorea365 → jobkorea365 리다이렉트 계획 스크립트(`plan_jobinkorea_
  consolidation.py`)는 작성만 하고 실행은 보류(사용자 지시, 나중에 진행).
