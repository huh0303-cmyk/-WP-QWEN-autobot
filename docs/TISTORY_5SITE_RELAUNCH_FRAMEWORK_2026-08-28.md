## 원칙

- 기존 블로그의 이름·주제·검색 이력을 존중하며 전혀 다른 분야로 갈아엎지 않는다.
- 다섯 곳을 동시에 대량 가동하지 않는다. 한 곳씩 점검하고 시험 글을 만든 뒤 다음 사이트로 넘어간다.
- 자동화는 초안 생성과 검수 준비까지만 담당한다. 공개 발행은 사람의 최종 확인 뒤에만 한다.
- WordPress·Blogger·다른 Tistory의 글을 복사하거나 문장만 바꿔 재사용하지 않는다.
- 의료·보험·자격·반려동물 건강처럼 신뢰가 중요한 글은 공식 또는 1차 출처와 기준일을 요구한다.

## 사이트별 재가동 절차

각 사이트는 아래 6단계를 하나씩 통과해야 한다.

1. **현황 감사**: 공개 URL, 최근 글, 카테고리, 소개, 스킨, 모바일, robots, sitemap, 검색 노출, 광고 상태를 읽기 전용으로 기록한다.
2. **기초 정비안**: 제목·설명·카테고리·필수 페이지·메뉴·검색 도구 상태를 정리하되 변경 전 값을 보존한다.
3. **콘텐츠 지도**: 핵심 축별 기둥글, 하위글, 검색 의도, 공식 출처 후보를 만든다.
4. **시험 초안 1건**: 다른 플랫폼과 겹치지 않는 독창적 글을 생성하고 비공개 검수 상태로 둔다.
5. **사람 검수**: 사실성, 출처, 제목, 이미지 권리, 광고 정책, 모바일 가독성을 확인한다.
6. **수동 공개 후 관찰**: URL·색인·오류·초기 반응을 확인한 뒤에만 다음 글 또는 다음 사이트를 연다.

## 재가동 속도

- 1주차: 1번 사이트 감사·정비·시험 초안 1건
- 2주차: 1번 결과 검토 + 2번 사이트 시작
- 이후: 앞 사이트에서 치명적 문제가 없을 때만 다음 사이트를 연다.
- 초기 4주 동안 사이트당 주 2~3건을 상한으로 삼는다. 품질과 실제 운영 가능성을 확인하기 전에는 일 1건 체제로 올리지 않는다.
- 자동 예약 공개는 전면 금지한다.

## 글 1건의 최소 계약

- 한 가지 검색 의도를 완결해서 해결한다.
- 제목, 도입, 목차, 예시, 결론을 해당 사이트 전용으로 새로 작성한다.
- 핵심 사실과 날짜에는 확인 가능한 출처와 기준일을 둔다.
- 카테고리는 사이트의 허용 목록에서 하나만 선택한다.
- 태그는 관련 명사형 표현만 사용한다.
- 이미지가 필요하면 주제 일치·권리·ALT를 확인한다. 불필요하면 억지로 넣지 않는다.
- 유사 제목·본문·출처 URL 중복 검사를 통과해야 한다.
- 초안 검수표가 통과하지 않으면 공개하지 않는다.

## 현재 안전 상태

- 다섯 사이트 모두 `launch_enabled=false`이다.
- 일일 계획기는 명시적으로 열린 사이트만 작업 대상으로 삼는다.
- 현재는 0개가 열려 있으므로 예약 워크플로가 글을 생성하거나 공개하지 않는다.
- 첫 사이트를 열기 전에 실제 관리자 설정 감사와 콘텐츠 지도 승인이 필요하다.
