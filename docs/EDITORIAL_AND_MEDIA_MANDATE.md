# 편집·이미지·알림 고정 원칙

이 문서는 WordPress, Blogger, Tistory, SNS 및 제휴 콘텐츠에 공통 적용하는 필수 운영 규칙이다.

1. 글에는 모델명, 프롬프트, 생성 과정, "AI가 작성", 상투적인 AI 서론·결론 등 제작 흔적을 남기지 않는다. 사실·출처·수정 이력은 숨기지 않는다.
2. 이미지 생성 순서(2026-08-29 사용자 확정·GitHub 박제): ① **Nano Banana가 무료로 제공되는 경우에만 1회 먼저 시도**한다. 무료 여부가 확인되지 않거나 유료 계정·유료 호출이면 건너뛴다. ② Nano Banana가 실패하거나 무료가 아니면 Replicate `black-forest-labs/flux-schnell` 1회 시도 ③ 실패 시 `bytedance/sdxl-lightning-4step` 1회 시도 ④ 실패 시 `jyoung105/sdxl-turbo` 1회 시도 ⑤ 모두 실패하면 다른 이미지·스톡·인포그래픽으로 대체하지 않고 무이미지 처리한다. 글당 최대 1장, 본문과 직접 관련된 이미지만 사용하며 자연스러운 ALT를 입력한다.
3. 황금 주제어는 매일 최신 검색 흐름과 공식 출처를 조사해 추출한다. 정부지원·장려금·시간표·예매·정책 글은 당일 공식 출처 확인이 없으면 발행하지 않는다.
4. 제목은 구체적인 사람의 상황·감정·이익·불안을 자연스럽게 담되 과장하거나 사실을 왜곡하지 않는다. 기계적인 번호 나열, 동일 문형 반복, 상투적인 AI 제목을 금지한다.
   - **제목은 모든 글의 최우선 텍스트 요소다.** 감성적 후킹, 궁금증, 독자의 실익을 함께 담아 실제로 클릭하고 싶게 만든다.
   - 낚시성 과장·거짓 약속은 금지한다. AI식 상투어, 반복 제목 공식, 과거 글 또는 다른 플랫폼과 유사한 제목은 `QUALITY_FAIL`로 차단한다.
   - **첫 이미지는 제목과 동급의 최우선 요소다.** 제목 속 구체적인 사람·상황·감정·이익을 즉시 이해할 수 있게 시각화하며, 무관한 장식 이미지는 사용하지 않는다.
5. 플레이리스트 썸네일은 기존 영상의 고화질 대표 화면 한 장에 로컬 글자 처리를 적용한다. 썸네일을 위한 영상 생성과 유료 이미지 API 호출은 금지한다.
6. Tistory의 정부지원금·장려금·시간표·예매 글은 확인한 핵심 정보를 모바일 카드뉴스 화면으로 함께 만든다. 카드뉴스는 로컬 HTML/CSS로 생성하며 이미지 API를 호출하지 않는다.
7. Blogger에는 한국 정부지원금·장려금·생활지원 정보를 다루는 한국어 전용 채널 하나를 둔다. 공식 출처와 기준일을 필수로 표시한다.
8. 실행 완료 후 카카오톡과 `huh0303@gmail.com`으로 결과를 보고한다. 보고에는 모바일에서 열 수 있는 실행 결과 링크와 편집·업로드 링크를 포함한다.
9. 이미지 API 비용은 위 고정 순서와 글당 1장 한도 안에서만 허용한다. Nano Banana 무료 1회 후 Replicate 3개 모델을 각각 최대 1회만 시도하며, 추가 재시도·다른 유료 모델·자동 확장은 금지한다.
10. 글쓰기 파이프라인 단계(2026-08-28 사용자 지시, 강제 적용):
    ① Gemini 2.5 Flash로 초벌 작성
    ② 실패하거나 품질 기준 미달이면 ChatGPT(OpenAI)가 재작성
    ③ Claude가 문법·문체·구조·팩트·SEO 최종 감리
    ④ 위 단계를 통과한 결과만 비공개 초안(draft)으로 저장
    ⑤ `huh0303@gmail.com`으로 모바일 승인 요청 메일 발송 — 사용자가 실제 워드프레스 편집 화면 링크를 열어 직접 발행/예약해야 공개됨(자동 공개 금지, [[모바일 승인 이메일 링크 수정 참고]]).
11. WordPress·Blogger·Tistory 5계정은 동일한 황금키워드 점수 선정과 70점 품질 게이트를 쓴다. 단, 뉴스룸 2개는 키워드 파일 대신 최신 RSS 헤드라인을 취재 주제로 쓴다.
12. 플랫폼 간 복사·붙여넣기는 절대 금지한다. 동일 사실을 활용해도 검색의도·제목·목차·문장·사례·체크리스트·FAQ를 플랫폼별로 새로 작성한다. 문장, 문단 순서, 제목 구조가 유사하면 승인 대기 초안에도 올리지 않고 `QUALITY_FAIL` 처리한다.
13. Blogger 글은 짧은 명사형 관련 검색어 라벨을 글마다 8~14개 범위에서 다르게 선정한다. 검색 설명(meta description)은 반드시 100~120단어로 작성하고, 누락되거나 범위를 벗어나면 초안 생성을 차단한다.
14. 모든 WordPress·Blogger·Tistory·뉴스 글은 3자 상호견제 게이트를 의무 적용한다. Gemini는 초안 작성 후 독립 자체점검, GPT는 팩트·구조·SEO·독창성을 별도로 검토하고 필요 시 재작성, Claude는 최종 문법·문체·팩트·정책 감리를 수행한다. 세 모델이 모두 `ok=true`를 반환해야만 검토 대기 초안을 만들 수 있다. 단일 모델 승인, 검사 생략, 키·한도 오류 시 우회 통과를 금지하고 `CONSENSUS_FAILED` 처리한다.

이 원칙의 변경은 사용자의 명시적 지시와 별도 Git 커밋이 필요하다.
