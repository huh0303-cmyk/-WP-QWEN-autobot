# 쿠팡 파트너스 사이트별 상품 배치 표준 SOP

- 적용일: 2026-10-31
- 적용 범위: London Project에서 관리하는 모든 WordPress 및 블로그 사이트
- 목적: 사이트 이름만 지정하면 사이트별 상품 마스터 구축부터 기존 글 일괄 삽입·검증까지 같은 순서로 신속하게 수행한다.

## 1. 절대 기준: 글 하나당 6~10개 상품

- 각 기존 글에는 **최소 6개, 최대 10개**의 상품 카드를 배치한다.
- 기본 목표는 6~8개이며, 글의 길이·독자층·상품 적합성이 충분하면 9~10개까지 확장한다.
- 상품 1개만 삽입하는 방식은 금지한다. 5개 이하도 완료로 인정하지 않는다.
- 상품 수를 채우기 위해 무관하거나 수요가 낮은 상품을 억지로 넣지 않는다. 적합한 상품이 부족하면 해당 사이트의 상품 마스터를 먼저 보강한다.

## 2. 상품 구성 원칙

각 글의 6~10개 상품은 다음 우선순위로 구성한다.

1. **본문 주제 직접 관련 상품 1~2개**: 글의 제목·본문과 직접 연결되는 제품만 선택한다.
2. **스테디셀러·대중 인기 상품을 나머지 중심으로 구성**: 꾸준한 수요, 폭넓은 독자층, 실용성, 구매 접근성을 고려한다. 단일 글 주제에만 갇히지 말고 해당 사이트 독자가 실제로 살 법한 범용 상품을 포함한다.
3. **고가/고단가 후보 1개**: 노트북, 태블릿, 모니터, 가전 등 사이트 독자와 맞고 구매 타당성이 있는 상품을 고려한다. 무관한 고가품을 억지로 넣지 않는다.
4. **생활 필수·실용 상품**: 충전기, 보조배터리, 이어폰, 가방, 생활·주방용품, 소형가전, 침구 등 해당 독자층에 맞는 상품을 활용한다.
5. 상품 구성은 위 유형을 중복 계산하지 않고 최종 6~10개가 되도록 조합한다. 주제 직접 관련 상품만으로 전체를 채우지 않는다.

## 3. 제외 및 주의 규칙

- 장갑, 안전화, 산업용 PPE, 특수 공구 등은 제조업·현장 안전·작업장 관련 글처럼 직접 수요가 명확한 경우에만 사용한다.
- 일반 취업, 비자, 생활정보, 건강정보 글에 산업용품을 관성적으로 넣지 않는다.
- 건강 사이트에서는 건강기능식품·의료 관련 상품의 효능을 과장하거나 질병 치료를 암시하지 않는다. 제품 설명과 법적 표시를 확인하고, 독자에게 구매 전 전문가·공식 안내 확인을 권한다.
- 판매 여부, 상품 페이지, 가격, 이미지, 공식 제휴 코드가 확인되지 않은 상품은 사용하지 않는다.
- 특정 상품을 반복해서 모든 글에 무차별 삽입하지 않는다. 글별로 6~10개 조합과 노출 순서를 다양화한다.

## 4. 사이트별 상품 마스터

- 상품 마스터는 플랫폼 단위가 아니라 **각 개별 사이트/블로그 단위**로 별도 구축한다.
- 사이트 고유 주제와 독자층에 맞춰 후보 상품을 조사하고, 스테디셀러·인기 실용품·고가 후보를 함께 확보한다.
- 상품별 필수 기록: 상품명, 카테고리, 독자 적합성, 공식 Coupang Partners 단축 URL, 공식 이미지+텍스트 HTML 또는 이미지 URL, 캡처 일자, 검증 상태, 사용 제한/적합성 메모.
- 사이트 마스터의 후보 풀이 부족하면 글에 임의의 상품을 삽입하지 말고 상품 확보 단계로 돌아간다.
- 쿠팡 파트너스 계정에 로그인한 상태에서 실제 생성된 본인 계정 링크와 공식 크리에이티브만 사용한다. URL·이미지 주소·제휴 태그를 추측하거나 수작업으로 만들어내지 않는다.

## 5. 기존 글 일괄 작업 순서

사이트 이름만 전달받으면 다음을 한 번의 표준 파이프라인으로 진행한다.

1. 사이트 연결/권한 및 CMS, 테마, 글 편집 구조 확인.
2. 공개 상태의 기존 글 전체 목록과 총 개수 확보. 페이지네이션 누락 여부 확인.
3. 글 제목·본문·카테고리·태그를 분석해 사이트 독자층과 글별 주제 상품 1~2개 후보 도출.
4. 사이트별 스테디셀러·생활 필수품·고가 후보 상품 마스터를 확보하고 공식 제휴 크리에이티브 검증.
5. 각 글에 6~10개 상품을 배치하는 글별 매핑표 작성. 한 상품만 들어가는 fallback은 금지.
6. 기존 본문에 일관된 반응형 상품 카드 그리드와 제휴 공시 문구를 삽입.
7. 기존 콘텐츠·제목·slug·날짜·발행 상태·대표 이미지·카테고리·태그·SEO 메타·기존 광고 블록을 보존한다. 원칙적으로 본문 필드만 변경한다.
8. 이미 제휴 상품이 있는 글은 중복 삽입하지 말고 현재 상품 수를 확인한 뒤 6~10개 기준에 미달하면 기존 상품을 보존하면서 보충한다.
9. 공개 글만 수정한다. 초안/비공개 글을 공개로 바꾸지 않는다. 글 삭제 금지.
10. 각 글 저장 후 다시 읽어 상품 카드 수, 공식 링크 수, 이미지 URL, 공시 문구, 글 상태·날짜·대표 이미지 보존을 확인한다.
11. 실제 프런트엔드에서 대표 샘플 및 모바일 표시를 확인한다.
12. 전체 대상 수, 기준 충족 수, 미달/실패 수, 중복 skip 수를 보고한다. 기준 미달 글은 완료로 보고하지 않는다.

## 7. 성능·실행 효율

- 가능하면 사이트 전체 글 목록과 상품 마스터를 먼저 수집한 뒤, 글별 매핑을 일괄 생성하고 배치 단위로 업데이트한다.
- 개별 글마다 불필요한 API 호출을 반복하지 않는다. 단, 저장 후 read-back 검증은 생략하지 않는다.
- 실패한 글만 원인을 기록하고 안전하게 재시도한다. 성공한 글을 다시 덮어쓰거나 중복 삽입하지 않는다.
- API 사용량/한도 초과 시 실제 작업이 중단된 지점을 기록하고, 한도 해제 후 미완료분만 이어서 수행한다.
- 도구 한도 때문에 실행할 수 없으면 완료했다고 말하지 않고, 차단 사유와 재개 가능 시점을 명확히 보고한다.

## 8. 완료 판정

사이트 작업은 다음 조건을 모두 만족해야 완료다.

- 모든 대상 공개 글에 상품 카드가 6~10개 존재한다.
- 모든 상품의 공식 제휴 링크와 이미지가 확인된다.
- 공시 문구가 표시된다.
- 기존 글의 상태 및 핵심 메타데이터가 보존된다.
- 저장 후 재조회 검증이 성공한다.
- 최종 보고서의 대상 글 수와 결과 합계가 일치한다.

**JobKorea365 보완 지시:** 기존 16개 및 후속 실행에서 추가된 글을 포함해 전체 공개 글을 다시 조사한다. 현재 한두 종류 상품만 들어간 글은 완료 처리하지 말고, 본 SOP의 6~10개 기준에 맞춰 스테디셀러 중심으로 보충한다. 장갑 등 산업용품은 직접 관련된 글 외에는 제거/대체를 검토하되, 기존 콘텐츠를 훼손하지 않고 제휴 영역만 수정한다.

## 9. London Project 표준 실행 순서 — 매번 재질문/재탐색 금지

사이트 작업은 아래 순서를 고정한다. 사용자가 사이트명을 지정하면 이 순서 전체를 자동으로 이어서 수행하며, 이미 확인한 경로·명령·필드명을 다시 사용자에게 묻지 않는다.

1. **작업 큐 결정:** 최신 일일 방문자 리포트에서 `yesterday_visitors` 내림차순으로 정렬한다. `LOCKED` 사이트는 절대 건드리지 않고 건너뛴다. 이미 완료 보고서와 공개 검증이 있는 사이트도 건너뛰며, 실패/미완료 사이트는 다음 신규 사이트보다 먼저 복구한다.
2. **기존 자산 재사용:** GitHub `data/affiliate/fleet-placements.json`, 사이트별 `data/affiliate/*verified*.json`, 캡처 NDJSON, 최근 Actions artifact를 먼저 확인한다. 동일 사이트에 유효한 상품 마스터가 있으면 새로 검색하지 말고 재사용한다.
3. **사이트 사전점검:** WordPress REST API, 공개 글 전체 수, 페이지네이션, 인증 secret 존재 여부를 확인한다. REST 인증 401/403 또는 SSL/DNS 실패가 있으면 그 사이트를 BLOCKED로 기록하고 원인을 바로 해결한다. 실패 사이트를 성공으로 간주하거나 다음 사이트로 조용히 넘어가지 않는다.
4. **상품 마스터 구성:** 해당 사이트 전용으로 6~10개 상품을 확보한다. 기본 구성은 주제 직접 관련 1~2개 + 독자층에 맞는 스테디셀러/실용품 + 적합한 고가 후보 1개다. 글마다 조합과 순서를 조정한다. 8개를 사용할 때는 주제/생활/건강/뷰티 2개씩을 기본 조합으로 삼되, 사이트 특성상 부적합한 카테고리는 적합한 대체 카테고리로 구성한다.
5. **공식 크리에이티브 확보:** 로그인된 Coupang Partners 포털에서 상품을 검색하고, 상품별 링크 생성 후 공식 블로그용 HTML 태그를 선택해 복사한다. `affiliate_url`, `official_image_url`, `official_blog_html_tag`, 상품명, 캡처 시각, `verified_account_owned=true`, `capture_source=coupang_partners_portal`를 저장한다. 링크는 `https://link.coupang.com/a/...` 형식이어야 하며, 태그 안의 링크와 이미지가 각각 저장된 값과 일치해야 한다. 임의 생성/추측/다른 계정 링크는 금지한다.
6. **글별 매핑:** 사이트의 공개 글 제목·본문·카테고리와 상품 적합성을 비교해 각 글마다 6~10개를 매핑한다. 상품 마스터는 사이트별로 분리한다. 한 사이트의 상품을 다른 사이트에 무차별 복제하지 않는다.
7. **Dry-run:** 전체 대상 글의 공개 상태, 상품 수, 고유 제휴 URL, 공식 이미지, 공시 문구, 중복 여부, 원본 콘텐츠 보존 조건을 검증한다. 오류가 1건이라도 있으면 Apply를 실행하지 않는다.
8. **Apply:** Dry-run 통과 후 GitHub Actions의 `coupang-partners-fleet.yml`을 해당 도메인 하나만 지정해 실행한다. 동시 다중 사이트 Apply는 하지 않는다. 기존 콘텐츠·제목·slug·날짜·상태·대표 이미지·카테고리·태그·SEO 메타는 보존하고 본문 제휴 영역만 변경한다.
9. **검증:** Actions artifact에서 대상/성공/실패 수를 확인한다. WordPress REST read-back과 공개 렌더링에서 링크·이미지·공시 문구를 검증하고, 대표 PC/모바일 화면을 확인한다. 성공 수와 대상 수가 일치하지 않으면 완료 처리하지 않는다.
10. **기록 후 다음 사이트:** 상품 마스터, 글별 매핑, 캡처 원본, Dry-run/Apply 보고서, 실행 시각, commit SHA, Actions run URL, 오류/재시도 상태를 GitHub에 저장한다. 현재 사이트가 완료 또는 명확한 BLOCKED로 기록된 뒤에만 방문자 순위상 다음 미완료·비잠금 사이트로 넘어간다.

## 10. 고정 운영 규칙

- 기본 실행 단위는 **사이트 하나씩 순차 실행**이다. 한 사이트의 상품 마스터부터 공개 검증까지 마친 다음 다음 사이트를 시작한다.
- 사이트별 진행상태는 `NOT_STARTED → INVENTORY → PRODUCT_MASTER → POST_MAP → DRY_RUN → APPLY → VERIFIED`로 기록한다. 실패는 `BLOCKED_AUTH`, `BLOCKED_CAPTURE`, `BLOCKED_MAPPING`, `BLOCKED_VERIFY` 등 원인을 구분한다.
- 동일한 오류를 반복 재현하기 전에 기존 Actions 로그, artifact, 캡처 NDJSON, 최근 성공 사이트의 스크립트와 설정을 먼저 읽는다.
- 포털 UI 자동화는 기존에 성공한 캡처 스크립트와 순서를 재사용한다. 새 스크립트는 기존 캡처 성공 여부를 확인하지 않은 채 별도로 실행하지 않는다.
- 사용자에게는 이미 GitHub에 저장된 절차를 다시 설명하거나 수동 작업을 요청하지 않는다. 실행 결과, 막힌 정확한 단계, 다음 자동 실행 항목만 간단히 보고한다.
- LOCKED 목록은 저장소의 사이트 정책/레지스트리를 단일 기준으로 사용한다. 사용자가 명시적으로 해제하기 전까지 수정·발행·상품 삽입을 금지한다.
