# London Project AI 운영팀 설계서

작성일: 2026-11-06
상태: 설계 기준 / 기존 실행 엔진 변경 금지
정본 저장소: huh0303-cmyk/-WP-QWEN-autobot

## 1. 목적

기존 런던프로젝트의 발행 공장을 교체하지 않고, 다섯 개 플랫폼 운영팀을 AI 에이전트 조직으로 구성한다. 목적은 검증된 콘텐츠 발행, 유입 성장, 제휴 및 광고 전환, 실제 순매출 극대화다.

## 2. 조직

- 운영본부장(총괄 PM): 이사장 지시를 실행 가능한 업무로 분해하고 우선순위·비용·성과를 관리한다. 게시 성공을 스스로 선언할 수 없으며 결정론적 감사 증거를 요구한다.
- YouTube팀: 채널별 주제·대본·음성·영상·썸네일·업로드·공개상태 검증을 담당한다. 기존 VPS YouTube Factory만 호출한다.
- TikTok팀: 세로형 숏폼 기획·각색·자막·게시·성과 분석을 담당한다.
- 블로그팀: WordPress 25개와 Blogspot 33개를 각각 독립 목적지로 운영한다. 기존 WordPress Factory와 Blogger Factory만 호출하며 서로의 성공 여부에 의존하지 않는다.
- Facebook팀: 페이지별 콘텐츠 각색·게시·링크 유입·성과 분석을 담당한다.
- Instagram·Threads팀: Instagram 릴스/캐러셀과 Threads 텍스트를 별도 형식으로 제작하고 게시·성과를 관리한다. 동일 문구 복사 게시를 금지한다.
- 공통 수익 분석 기능: 별도 발행팀이 아니라 각 팀에 제공하는 공유 분석 기능이다. 광고·제휴 클릭·전환·수수료·환불·순매출 데이터를 연결된 실제 데이터에서만 집계한다.

## 3. 팀 내부 에이전트 역할

각 팀은 다음 역할을 논리적으로 분리한다. 초기에는 별도 상시 프로세스 5개를 띄우지 않고, 기존 실행 엔진에서 필요할 때 작업 단위로 호출한다.

1. Team Lead / Planner: KPI, 콘텐츠 캘린더, 우선순위, 작업 분해.
2. Researcher: 검색 의도, 트렌드, 경쟁 콘텐츠, 근거 출처 조사.
3. Producer: 플랫폼별 원고·영상·이미지·자막 등 제작 요청 구성.
4. QA / Policy Reviewer: 중복, 사실성, 저작권, 플랫폼 정책, 링크 및 추적 파라미터 점검.
5. Publisher: 해당 플랫폼의 기존 발행 엔진에 작업 전달. 인증된 계정만 사용.
6. Performance Analyst: 게시 ID와 실제 URL을 확인한 뒤 노출·조회·클릭·전환·매출을 분석하고 다음 실험을 제안.

## 4. 표준 업무 흐름

REQUESTED → PLANNED → ASSIGNED → PRODUCED → QA_PASSED → READY_TO_PUBLISH → PUBLISHED_PENDING_AUDIT → VERIFIED_COMPLETE

- 작업마다 고유 task_id, 플랫폼, 대상 계정/사이트, 콘텐츠 식별자, 담당 팀, 비용, 상태, 증거를 기록한다.
- 게시 ID와 실제 공개 URL 또는 YouTube video_id·정확한 channel_id·privacyStatus가 확인되지 않으면 성공으로 처리하지 않는다.
- 자동 재시도는 기존 정책대로 최대 1회다.
- 403, 429, quota, billing, OAuth 오류는 해당 provider/목적지만 차단하고 다른 목적지는 계속한다.
- 계정 권한 미검증, OAuth 미연결, API 미승인인 플랫폼은 게시하지 않고 NEEDS_ATTENTION으로 남긴다.
- AI 에이전트는 VERIFIED_COMPLETE를 직접 부여하지 않는다. 기존 결정론적 Audit Engine만 부여한다.

## 5. 수익 최적화 운영

주간 단위로 다음을 비교한다.

- 콘텐츠별 조회/방문, 검색 유입, 구독/팔로우 증가
- 링크 클릭률(CTR), 제휴 전환율, 주문/승인 건수
- 광고 및 제휴 수익, 취소/반품, 수수료, 순매출
- 콘텐츠 제작비·API 비용·렌더링 비용을 반영한 순기여이익
- 플랫폼/계정/주제/상품별 성과

실제 연결된 원천 데이터가 없는 수치는 추정하지 않는다. 조회수만 높은 콘텐츠보다 순매출 기여가 높은 콘텐츠를 우선 확대한다. 충분한 표본이 없으면 승자를 선언하지 않고 실험을 계속한다.

블로그 제휴 영역은 사용자가 정한 사이트별 상품 구성과 실제 추적 URL을 사용한다. Coupang 링크는 글 하단 10개 상품 구성을 기본 기준으로 하되, 상품 적합성·재고·실제 추적 링크를 검증한다. 제휴 고지 및 플랫폼 정책을 준수한다.

## 6. 기존 런던프로젝트와의 경계

- WordPress 25, Blogger 33, YouTube VPS Factory의 코드와 스케줄을 이 문서만으로 변경하지 않는다.
- Facebook, Instagram, Threads, TikTok은 계정별 게시 권한 및 공식 API/연결 상태가 확인된 범위만 활성화한다.
- Control Korea365는 읽기 전용 관제를 유지한다. 게시·생성·큐 실행을 직접 수행하지 않는다.
- 기존 destination별 독립 queue/state, 최대 1회 retry, provider circuit-breaker, append-only activity ledger를 그대로 따른다.
- 기존 뉴스룸 2개, Tistory/Naver, 추가 YouTube 채널은 이번 5개 팀 범위에 임의로 편입하지 않는다.
- WPVibe는 사용하지 않는다.
- 새 유료 API, 유료 SaaS, 유료 이미지 생성은 이사장 사전 승인 없이 추가하지 않는다. 무료 이미지 우선, 이미지가 부적합하면 무이미지 경로를 허용한다.

## 7. 단계별 구축

### Phase 0 — 안전한 기반 확인
기존 저장소·워크플로·큐·인증·계정별 발행 권한을 읽기 전용으로 점검한다. 현재 발행 장애를 새 에이전트 도입 문제와 혼합하지 않는다.

### Phase 1 — 조직 및 작업 계약
팀별 책임, 입력/출력 JSON 계약, 상태 전이, task_id, 감사 증거, 비용 상한을 문서화한다. 기존 발행 기능은 변경하지 않는다.

### Phase 2 — Shadow Mode
에이전트가 주제 선정, 초안, 작업 배정, 수익 분석을 만들되 실제 게시하지 않는다. 기존 결과와 비교해 품질·중복·비용을 검증한다.

### Phase 3 — 승인 게시
계정 인증과 플랫폼 게시 권한이 확인된 목적지부터 제한적으로 게시한다. 실제 게시 ID와 URL 감사까지 통과해야 완료다.

### Phase 4 — 성과 기반 최적화
연결된 분석/제휴 데이터가 확보된 플랫폼부터 실험을 수행한다. 승자 주제와 상품 구성을 확대하고 저성과 포맷은 줄인다.

## 8. 운영 승인 기준

- 기존 플랫폼 공장에 장애를 전파하지 않을 것
- 비용 정책을 위반하지 않을 것
- 계정 권한 확인 전 게시하지 않을 것
- 실제 게시 증거 없이 완료 보고하지 않을 것
- 중복 콘텐츠·저작권 위반·허위 수익 수치를 만들지 않을 것
- 사람의 승인 단계가 필요한 항목은 승인 없이 우회하지 않을 것
