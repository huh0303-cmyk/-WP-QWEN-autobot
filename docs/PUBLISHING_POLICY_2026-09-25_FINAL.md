# Publishing Policy — 2026-09-25 Final

## Business goal

The London Project is optimized for Google AdSense and audience growth. The primary operating KPIs are daily visitors, pageviews, Google indexed URLs, AdSense approval status, and AdSense revenue. `k-health365.com` is the currently approved AdSense center and benchmark.

## Canonical cadence

- Regular WordPress: **25 total including k-health365.com**, one verified public post per site per KST day.
- Newsrooms: **koreanews365.com** and **theseouljournal.com**, **3–10 verified breaking/news posts per newsroom per KST day** when valid source leads exist. Never invent filler.
- Blogspot: **33**, one verified public post per blog per KST day.
- Tistory: **5**, one verified public post per site per KST day through the authenticated local registrar.
- Naver: start with **N1 = huh0303**, one verified public post per KST day; N2/N3 remain disabled until explicitly mapped.
- Instagram, TikTok, Facebook and Threads: one verified public post per connected account per KST day after account-specific write authorization.
- YouTube core production set only: **5 playlist + 5 knowledge channels**, each 2–3 productions per seven-day cycle.
- Other connected YouTube strategic channels are not part of the core 10 cadence; where their own channel policy enables publishing, their default target is one publication per day.

## Verification rule

A login session, configured destination, queued job, generated article, draft, or accepted API request is **not** publication proof. A channel is publish-connected only after exact identity, write permission, and a receipt-backed remote publication are verified.

## Search and monetization rule

Google indexing is revenue infrastructure. Sitemap failures, accidental noindex, crawl blocks, stale GSC evidence, low-value duplication and broken canonical/index signals are priority defects. Never hide or delete a known indexed/traffic URL merely to simplify the site.

## Secret handling

GitHub stores code, policy, schedules, secret names and non-sensitive IDs only. Tokens/passwords remain in GitHub Secrets, the VPS protected environment, or the authorized local browser/runtime.
