# Coupang Partners Multi-Site Execution SOP

Version: 2026-10-31
Project: London Project
Repository: huh0303-cmyk/-WP-QWEN-autobot

## Mission
Add the user's own Coupang Partners product-share creatives to existing, already-published articles. This is an append-only content update, not new article writing and not new article publishing.

## Account ownership — mandatory
1. Use only product links and HTML creatives generated inside the user's authenticated Coupang Partners account.
2. Never construct, guess, rewrite, or borrow affiliate URLs from another account, another site, search snippets, or third parties.
3. Preserve each generated short URL and official image creative exactly as captured.
4. Do not manually add or replace tracking IDs.
5. A product without a verified account-generated link AND official image creative is not eligible for insertion.

## Per-site sequence
The user supplies site names in sequence. For each site:
1. Create a separate site catalog. Never reuse another site's catalog by default.
2. Read published articles: title, permalink, categories, tags, and full content.
3. Build a site-specific candidate pool (initial target 30–50); candidates remain unverified until portal links and creatives are captured.
4. Capture actual products in the user's logged-in Coupang Partners portal. Save exact product title, generated link, official image URL, exact HTML, capture date, and verification status.
5. Match products to articles using title AND body context, categories, and tags. Title-only matching is insufficient.
6. Exclude weak or unrelated matches. Never force placement.
7. Target 6–7 products/article only when 6–7 genuinely relevant verified products exist:
   - 2–3 directly relevant products;
   - 2 Korean daily-life / settlement essentials, only when relevant;
   - 2 higher-value products, only when contextually appropriate.
   If the verified relevant pool is insufficient, hold that article rather than insert unrelated products.
8. Rotate combinations and order with usage-count / last-used tracking to reduce repetition.
9. Dry-run first; inspect exact HTML for each target post.
10. Pilot a small set of already-published posts; append the affiliate module only.
11. Re-fetch permalinks and verify disclosure, exact affiliate hrefs, image src, rendering, and no duplicate insertion.
12. Expand sequentially by site only after pilot verification passes.

## WordPress safety
- Only update posts whose current status is exactly publish.
- Update only the content field.
- Never create a post or publish a draft/private post.
- Preserve status, date, title, slug, categories, tags, featured image, excerpt, SEO metadata, and all existing article text.
- Append a clearly delimited affiliate section; never replace existing content.
- Idempotency: detect the site marker and do not insert twice.
- Record before/after content hashes and post IDs in an audit report.
- Pilot first; no bulk write before pilot verification passes.

## HTML requirements
- Prefer exact official blog HTML generated by the portal.
- Preserve each product's unique generated href and official image src.
- Add rel="sponsored nofollow noopener" to the anchor while preserving target/referrerpolicy.
- Do not fabricate or substitute images.
- Include the disclosure in the affiliate section.

## Cloud execution and security
- Use GitHub Actions / approved cloud workflow, not a desktop-bound scheduler.
- Use the existing site-specific GitHub secret; never print or log secret values.
- Never commit credentials, cookies, session tokens, or partner account identifiers.
- Never run a K-Health365-only workflow for another site.
- WPVibe is disabled / quota exhausted; do not use it.
- Do not add paid APIs, paid SaaS, or paid image services.

## Per-site data contract
- data/affiliate/<site>-products.json: verified product catalog with provenance.
- data/affiliate/<site>-placements.json: article-to-product mapping.
- config/affiliate/<site>-rules.json: site identity, secret env key, matching and placement rules.
- reports/<site>-affiliate-audit-<date>.json: dry-run, pilot, write, and verification results.
- A site-specific workflow accepts explicit post IDs or a bounded pilot limit.

## Minimum product record
product_id, site, product_title, coupang_product_id, affiliate_short_url, official_image_url, official_blog_html, captured_at, capture_source, verified_account_owned, verification_status, price_at_capture, notes.

## Minimum audit record
Site, run ID, mode, target post IDs, status before/after, original content hash, updated content hash, inserted product IDs, exact affiliate hrefs, image URLs, disclosure check, duplicate check, permalink verification, errors, timestamp.
